# Elwood’s product-drop playbook

## Strategy

Keep a signature basic available and use smaller releases to give customers a reason to return. Concentrate creative production on launches that need to introduce a product or tell a distinct story. Use lighter coverage for variants and routine arrivals. Test the cadence against the team’s workload and the economics of each release.

**First action:** Pick one existing SKU that customers already buy and that you can replenish. Pull its recent availability, sales, return reasons and direct costs. Then choose one small follow-on release that the team can fulfill with confirmed stock.

**Assumption:** This playbook is for a small DTC apparel brand with a storefront, sales data and at least one stocked product. The roles, launch criteria and pilot below are proposed operating choices. For a pre-launch brand, start with SOP 1 and approve the sample and price before committing to the release calendar.

## SOPs

### 1. Approve the core product

**Owner:** Product lead. **Trigger:** New hero SKU or material fit, fabric or price change.

1. Write the target customer’s use case and specify desired fit, fabric or finish, and target retail price. For an existing SKU, pull sales while in stock and review fit-related returns and customer feedback.
2. For a new or revised product, give the supplier a reference and annotate the relevant attributes. Fit and wash the sample against agreed tolerances and record revisions.
3. Confirm costs and availability with operations. Pass the approved specification, sample notes, price and replenishment status to the launch owner.

**Done:** The product brief has a signed-off sample or existing SKU, a clear customer promise and an inventory plan. If fit, cost or supply is unresolved, revise the brief and hold the launch date.

### 2. Scope the release

**Owner:** Merchandising lead. **Trigger:** Weekly calendar review or material stock delay.

1. Confirm the SKU, inventory readiness, creative hours, fulfillment coverage and approver. Protect replenishment for the core SKU.
2. Use a **major campaign** for a new silhouette or story that needs dedicated assets. Use a **light release** for an approved variation that can use a product page, Stories and a native short video. These are proposed tiers for the test.
3. Record the date, tier, assets, primary owner, backup approver and go/no-go check. If production overruns, reduce optional assets. If inventory or fulfillment fails the check, move the date.

**Done:** Creative and operations can work from the same release brief.

### 3. Produce and check creative

**Owner:** Creative lead. **Trigger:** Release brief approved and representative sample available.

1. Write one customer-facing product promise and pick the proof the camera should show, such as sleeve fall, fabric drape or how a garment moves.
2. For a major release, plan editorial images around the brand setting and capture a channel-native short video around a single real use case. For a light release, use available clean product images and shoot a simple try-on or comparison clip.
3. Have the approver check brand fit, accurate SKU and color, legible sizing and a working destination link. Pass the approved files and link to ecommerce.

**Done:** Ecommerce has an approved asset set. Reshoot inaccurate product visuals or use approved assets that show the actual SKU.

### 4. Launch and review

**Owner:** Ecommerce and operations lead. **Trigger:** Inventory and assets are ready.

1. Check live inventory by size, mobile product page, fulfillment coverage, channel links and tracking. Hold the release if a critical check fails.
2. Publish the product and scheduled assets. Record stock, spend and staff hours.
3. Review initial sales and workload after seven days. Revisit returns at the end of the normal returns window. Record whether to repeat, simplify or pause the next release.

**Done:** The scorecard has an owner and a next-release decision, with any pending return data flagged.

## Pilot and measurement

Run one light release over two weeks using a proven basic and an available variant. In week one, record the baseline from a recent comparable release if one exists, agree a contribution and staffing floor or cap as appropriate, confirm stock and build the page and assets. In week two, launch and review at day seven. If no comparable release exists, use this run to establish the baseline and record any differences in price, stock, promotions or traffic before comparing a second run.

| Measure | Definition and data source | Review |
|---|---|---|
| Release contribution | Net product sales less product cost, variable selling and fulfillment costs, and incremental launch spend, from order and cost records. Update for refunds. | Day seven and after returns mature |
| Sell-through and core availability | Net units sold / starting sellable units, adjusted for units added during the window. Track core sizes out of stock separately using inventory records. | Daily and day seven |
| Team workload | Actual prep and launch hours against the agreed capacity cap, from the release log | Before launch and day seven |
| Channel response | Tagged product-page sessions and orders by asset, where tracking supports both | Day seven. Use as directional evidence. |

Repeat the light release if contribution meets the agreed floor and the team stays within capacity without interrupting core availability. Simplify or space out releases if hours exceed the cap. Pause the next release if stock, fulfillment or contribution misses the agreed minimum. If the first run works, use a comparable second release before increasing cadence.

## Skill test

**Walkthrough using a hypothetical washed tee:** The product lead confirms the current fit and approves a new color sample. Merchandising assigns a light release and hands creative the brief. Creative supplies product photos and a try-on clip. Ecommerce finds the new color’s size run has been delayed, so it holds the release and moves the date. If stock clears, ecommerce launches and uses the scorecard to decide whether to repeat.

The walkthrough exercised the stock-delay branch and confirmed that each SOP supplies the next step’s inputs. The pilot remains a plan. A real test needs the brand’s inventory, costs, sales history and available staff hours.
